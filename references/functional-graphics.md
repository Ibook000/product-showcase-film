# 功能动效

功能动效是使用效果的视觉示意，不是新一次真实操作、性能测试或识别结果。真实录屏、示意动画和生成素材在工程记录与交付说明中分别标明；不要为了画面美观把示意称为实测。

## 页面难看时的选择

- **功能动效**：重点是让人理解使用结果，重设计文本、选择、反馈与进度；不必重建整个后台或设置页。
- **真实局部精修**：真实软件本身是证据时，裁出目标控件、调整留白并放大，保留足够上下文。不要修改识别内容、状态或数据来伪造实际结果。
- **完整操作**：确实需要展示配置过程时使用。清理其他窗口与隐私信息，审查使用的整段，不只看封面帧。

## 因果关系优先

把触发动作、处理中状态和结果放在观众能对应的位置。内容变化要有依据，减少系统实现细节和不必要的设置项。

示例仅用于选择构件，不是每种产品都要拥有这些功能：

| 产品/功能 | 触发与结果 |
|---|---|
| 语音输入 | 按住录音 → 声波 → 逐字输入 → 松开完成 |
| 快捷编辑 | 选中 → 复制 → 插入新位置 → 粘贴 → 撤销 |
| 旋钮 | 转动 → 页面滚动或数值变化；按下 → 确认或静音 |
| 清洁工具 | 操作路径 → 处理前后区域对比，实际效果需要素材支持 |
| 充电或计时产品 | 启动 → 状态/进度变化 → 完成反馈，不虚构速度或续航 |
| 软件流程 | 同一个对象在步骤间保留身份和内容，不重复用无关界面替换 |

保持文字内容、选择范围、光标位置和撤销前后状态一致。复制应保留原句，粘贴才新增内容，撤销恢复上一状态。若要证明实际快捷键组合或输入焦点行为，检查代码或真实软件，不从图标猜协议。

## 提供的基础构件

`scripts/graphics.py` 使用相对画布坐标，提供 `title`、`typewriter`、`duplicate-undo`、`text-workflow`、`progress`、`scroll`、`carrier`。模板是起点：文字、字段、图形与布局应随产品改写。竖屏和较长文案需要重新审查构图，自动缩字不能保证好看。

单独拼接 `typewriter` 与 `duplicate-undo` 会产生两个独立覆盖层的淡出/淡入。需要保留同一输入区域时用 `text-workflow`：它在同一范围内完成输入、选中、复制、粘贴和撤销，`typing_fraction` 控制前段输入比例，默认 .48。更复杂的真实操作需任务状态时间线，不把套用模板声称为已经验证了软件行为。

`carrier` 可从一个屏幕比例坐标移向另一个，或使用模型投影锚点。精确连到实体零件时检查实际投影，而不是凭感觉放圆环。没有模型投影的素材不能引用三维锚点。

文案、操作状态、字体覆盖、对比度和边缘留白需要视觉检查。输出画幅改变后重看每种状态；不要把源渲染放大输出当作原生高分辨率证据。
