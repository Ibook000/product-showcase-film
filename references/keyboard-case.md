# 案例：语音快捷键盘

此案例用于解释取舍，不把其样式与硬件结构设为其他产品的默认值。

## 已知需求与依据

用户制作毕设项目展示，产品为语音快捷键盘。包含录音按键、快捷键、旋钮、桌面软件；用户确认轴体支持热插拔。目标是纯项目展示、音乐与交互音效，不要旁白，也不再讲 AI 设计电路板或复杂传输原理。

用户曾要求保留“按住录音 → 声波 → 逐字输入 → 松开完成”，快捷键展示选中、复制、粘贴、撤销，旋钮展示滚动/确认和音量/静音。它们适合作为动作—反馈—结果的例子，并非其他产品必需功能。

## 从反馈提炼的方法

| 用户反馈 | 有效调整 | 不应泛化成什么 |
|---|---|---|
| 原理和功能总是同一个画面 | 重新分镜，改变景别，增加动作与结果镜头 | 任意项目都要延长到几分钟 |
| 更喜欢原先版本，节奏慢 | 回到指定原片，保留其三维质感，缩短停留并对齐重音 | 继续加长不喜欢的新版，或仅全局倍速 |
| 软件页面难看 | 改成统一的功能动效，重点展示文字与状态变化 | 伪造真实软件操作记录 |
| 转场要无缝 | 同一三维场景连续取景；同一文本进入下一步；波形、圆环、进度条连接功能 | 所有镜头一律叠化就自动无缝 |
| 轴体可热插拔 | 用独立轴体和键帽对象分别离位、复装 | 只抬起键帽，或据动画反推轴体性质 |

## 实现与验证边界

该项目的后期版本采用原始工程三维模型与重设计功能动效，36 秒、24 FPS、120 BPM；这是案例参数。三维源渲染为 1600×900，最终输出为 1920×1080。语音与编辑画面是示意，不是新的识别性能或键盘实测。

没有使用生成式视频服务，不能据此声称 AI 首尾帧生成已验证。模型、光源和相机在原生三维场景内工作，使用正交轨道与取景宽度变化，不能描述成透视视差推轨。

过程暴露的失败包括相机被通用对象恢复循环重置、音轨依赖旧脚本、路径与字体写死、缓存只看文件存在和编码后峰值超标。通用工具针对这些问题做了显式对象集合、独立音轨、配置/系统发现、签名缓存和 AAC 后复测。

迁移到相机、家电、仪器、手持工具或软件时，应重新确定真实卖点、零件映射、使用结果、材质、光线、节奏和画幅；不要复制键盘的名称、坐标、颜色、按键数量或拆卸距离。
